## 二、8 分钟主线（推荐）

### 0:00–0:40　开场（不碰电脑，先给结论）

> "这是一个差旅助手。说一句『明天从北京去上海出差 3 天，预算 2000』，
> 它会先判断你要干什么，再并行调度能力，最后给一份能照着走的行程。
> 三个数字：**5 秒出 3 天行程**、**10 个技能**、**103 条测试全绿**。"

顺手点一下右侧栏的 **意图 / 日程**：

> "右边能看到它识别出的意图、实体和调度顺序 —— 不是黑盒。"

---

### 0:40–3:00　第一幕：一句自然语言 → 可执行行程（核心）

**输入**：

```
明天从北京去上海出差3天，预算2000
```

**预期**：约 4–6 秒，出现「北京至上海3天差旅行程」卡片，每天 2–3 段活动，带地铁/预算。

**要指的地方**（从上到下）：

1. 每天的时间轴、活动、交通方式；
2. 右上角「导出」——"可以带走，不是只能在网页里看"；
3. 右侧 SCHEDULE 的 `P1`——"查车票和排行程可以同时跑"。

**接着输入（体现多轮）**：

```
第二天下午安排见客户
```

**预期**：约 6 秒，第 2 天变成 `14:00-17:00 客户会议洽谈`。

> "它不是重新生成一遍，是接着上一版改。这就是短期记忆 + 上下文消解。"

---

### 3:00–4:30　第二幕：车票（刚修好的两个点，很出效果）

**输入**：

```
看看明早从北京去上海的高铁票有哪些
```

**预期**：车次卡片，15 趟，出发到达时刻、历时、二等/一等/商务座余票。
（首次查 12306 约 3–11 秒；慢就说"这是实时接口"。）

> "注意它把『明早』理解成了明天早上，还自动只留上午的车次。"

**紧接输入**：

```
列出来
```

**预期**：**0 秒**，卡片展开全部 15 趟。

> "这句『列出来』没有重新查一次，而是复用上一轮结果直接展开 —— 省一次网络请求，也省一次模型调用。"

---

### 4:30–6:30　第三幕：制度问答（HR 最有共鸣的一段）

**输入**：

```
上海住宿标准是多少
```

**预期**：2 秒内，答案 + 末尾「依据：《不同城市差旅注意事项》《阿里商旅差旅标准和规定》…」，卡片下方还能展开「来源文档」。

> "企业场景里，员工第一个问的往往不是『帮我订酒店』，而是『我能住多少钱』。
> 这类问题必须给依据，不能是模型编的。"

**输入**：

```
协议酒店有什么优惠
```

**预期**：答"比市场价低 10%–20%、有协议标识、房源优先保障"，同样带依据。

> "这句之前会被理解成『搜酒店』，给你 600 家酒店 —— 我们把它改成了政策问答。"

**输入**：

```
目前有哪些知识库
```

**预期**：列出 8 份文档（差旅标准、报销规定、预订指南、FAQ、紧急处理、平台指南、城市贴士、环保倡议）。

> "知识库就是公司的制度文档，换成贵司的 PDF 也能用。"

---

### 6:30–7:30　第四幕：记忆与账本

**输入**：

```
我出差喜欢坐高铁一等座
```

**预期**：偏好卡片，写入「高铁 + 一等座」，追问"需要我帮你规划高铁一等座的行程吗"。

> "说一次就记住，下次规划直接用。侧栏『偏好』里能看到。"

**输入**：

```
今天打车花了80元
```

**预期**：0 秒入账，右侧「费用」面板 +80。

**输入**：

```
100美元等于多少人民币
```

**预期**：2–3 秒，`667.61`（实时汇率）。

## 四、出问题怎么办（Plan B）

| 现象 | 处理 | 话术 |
|---|---|---|
| 车票 10 秒还没出 | 直接说"12306 实时接口有点慢"，等它；超过 20 秒切截图 `docs/screenshots/05-train.png`、`08-train-list.png` | "线上接口，网络波动" |
| 知识库首次很慢 | preflight 已预热；仍慢就切 `09-rag-answer.png` | "本地向量库在加载" |
| 模型报错 / 403 | `verify_llm.py` 看通道；主通道挂了会自动切备用，重发一次即可 | "我们做了多通道容灾，正好演示一下" |
| 页面白屏/卡死 | `.\stop-demo.ps1` → `.\start-demo.ps1`，30 秒恢复 | "重启一下，很快" |
| 完全没网 | 打开 `docs/showcase.html`（离线可用）+ 截图讲产品与架构 | "先看产品形态" |

**永远不要**在演示时：点朗读、清空记忆、连发两条（会排队）、演示空消息/超长文本。

## 五、HR 可能问的 8 个问题

**1. 这和携程/飞猪有什么区别？**
不是订票入口，是"制度 + 行程 + 记忆"的助手。员工先问标准、再问行程、最后才订票；前两步携程不管。

**2. 为什么用多智能体，一个大模型 prompt 不行吗？**
三个理由：可解释（侧栏能看到识别和调度）、可替换（技能是插件，换搜索源不动主流程）、可测试（16 条端到端用例，单 prompt 没法局部验证）。单 prompt 还很难稳定输出结构化 JSON。

**3. 成本高吗？**
规则快路由覆盖了大部分常见表达（"A 到 B + N 天"0 毫秒出意图），只有复杂表达才调模型；一次行程 1 次模型调用。按当前通道计价，单次在分币级。

**4. 数据安全？**
记忆落本地 JSON（可切 PostgreSQL），向量库本地 Milvus Lite；不接第三方分析。模型走 API，可换成公司内网模型（协议兼容就行）。

**5. 用户量上来怎么办？**
会话 LRU、Milvus 换集群版（改一行连接串）、Redis 缓存、PostgreSQL 持久化——接口都留好了。

**6. 知识库怎么维护？**
`data/documents/*.txt` 放文档，跑一次 `init_knowledge_base.py` 重建索引，30 秒。换公司制度只改文件。

**7. 出错怎么办？会不会胡说？**
答案强制带「依据」；检索不到就说没找到。模型挂了切备用通道，整链 110 秒封顶，不会无限转圈。

**8. 你负责哪部分？**
从意图识别、编排、10 个技能、前端到容灾和测试，全栈。
