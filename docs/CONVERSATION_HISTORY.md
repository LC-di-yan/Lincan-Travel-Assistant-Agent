# 聊天记录与新建对话

## 使用方式

- 左上角的「＋」打开一个新的独立对话，不删除之前的消息。发出第一条消息后，新对话才加入历史。
- 宽屏默认显示左侧「聊天记录」。窄屏点击左上角的侧栏图标打开；可按标题或消息里的关键词搜索，点开旧对话查看和继续。系统保留最近打开的会话指针，刷新会尝试还原。
- 左侧「聊天记录」是问答；右侧「行程」和右上角「个人中心」是原有的业务数据入口。行程、账本和已保存偏好不会随会话切换而重置。
- 切换会停止当前仍在生成的回复，已经提交的消息不会被删除。已保存的结果是当时的记录，不会因查看而重新查价、修改账本或提交预订。

## 身份与数据兼容

Web 沿用已有的签名浏览器身份，没有新增账号系统。同一身份的所有会话共用现有存储，有独立的会话标识；接口只读取当前身份的数据。更换浏览器、清除身份 Cookie 或更换服务端签名密钥后，不会自动恢复原身份的聊天记录。

旧版本已按会话保存的文字与助手摘要，可以直接按原会话回看。没有会话标识的早期消息集中在只读的「早期对话记录」；原先未保存的消息、已截断的细节或未保存的卡片无法还原。新版会保存新的追问、最终回复和受限的卡片快照，不重放旧的费用确认或行程保存操作。

恢复会话时只把本会话近期文字与有期限的追问状态用于接续，不将该用户的其他对话正文混入当前对话。原有偏好授权、费用确认、票价有效性规则继续生效。

## 发布前检查

1. 同时构建前端并更新后端，保留原数据目录和会话签名密钥。公开环境继续使用 HTTPS。
2. JSON 使用原用户文件，不需要数据迁移。若使用 PostgreSQL，备份后在授权维护窗口执行 [聊天展示列迁移](../db/migrations/005_chat_presentation.sql)，只新增可空字段和索引。没有迁移时可保存、读取文本，但不保留卡片和结构化接续状态。应用启动不自动执行迁移。
3. 用隔离测试身份验证：两条对话可搜索、刷新可重开、旧会话可继续、同一账本在两条对话均可见，第二身份不能读取。回退应用版本时不要用旧数据快照覆盖新记录。

## 本地验收

- Python：`python -m pytest -q tests/test_conversation_archive.py`。PostgreSQL 测试只允许本机独立的 `aligo_conversations_dev_test` 测试库，通过环境变量 `ALIGO_TEST_CONVERSATIONS_PG_DSN` 注入。
- 浏览器：用 `npm run build` 构建，然后运行 `python tests/run_isolated_browser_audit.py --assets <本地构建目录> --output <新的临时目录> --conversations`。该流程在回环地址启动独立服务，使用模拟铁路及天气数据，不访问线上存储。
