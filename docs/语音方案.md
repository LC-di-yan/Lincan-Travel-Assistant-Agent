# 语音输入 & 语音输出 — 技术方案

## 一、语音输入：Web Speech API（纯前端，零成本）

### 1.1 原理

浏览器内置 `SpeechRecognition` API，Chrome 和 Safari（含移动端）均支持中文（`zh-CN`）。语音在浏览器本地转为文字后填入输入框，与现有消息发送流程完全解耦，不需要任何后端改动。

### 1.2 架构

```
麦克风 → SpeechRecognition → 实时 interim 文字（显示在 textarea）
                          → 最终 final 文字 → 填入输入框 / 自动发送
```

### 1.3 前端改动

#### 新增 `web/src/hooks/useSpeechRecognition.ts`

```ts
const SpeechRecognition = window.SpeechRecognition || window.webkitSpeechRecognition
const recognition = new SpeechRecognition()
recognition.lang = 'zh-CN'
recognition.interimResults = true    // 实时中间结果
recognition.continuous = false       // 一句话结束后自动停止

// 暴露：
// - isListening: boolean
// - interimText: string      实时变动的临时识别文字
// - finalText: string        一句话确认后的最终文字
// - startListening(): void
// - stopListening(): void
// - isSupported: boolean     检测浏览器是否支持
```

#### 修改 `InputBar.tsx`

- textarea 右侧增加麦克风按钮（`Mic` / `MicOff`，lucide-react 已有）
- 点击调用 `startListening()`，按钮变为红色脉冲动画
- `interimText` 实时追加到 textarea 末尾（灰色斜体显示）
- 一句话结束后 `finalText` 合并到 textarea，用户手动发送或 Enter 确认
- AI 开始回复时自动停止收音

#### UI 细节

- 收音中动画：红色脉冲圆环 + "正在聆听..." tooltip
- 浏览器不支持时：隐藏麦克风按钮（`isSupported === false`）

### 1.4 兼容性

| 平台 | 支持情况 |
|------|----------|
| Chrome (桌面+安卓) | 完全支持 `zh-CN` |
| Safari (iOS/macOS) | 支持，需 HTTPS 或 localhost |
| Firefox | 不支持 |
| Edge | 完全支持 |

### 1.5 成本

**零**。无需 API Key、无需后端、无需网络请求。语音识别在浏览器本地完成。

## 二、语音输出：MiMo-V2.5-TTS 流式合成

### 2.1 可行性

项目后端目前使用 **阿里云 MAAS** 调用 GLM 大模型（`config.py` LLM_CONFIG，`base_url=...aliyuncs.com/compatible-mode/v1`），**与 MiMo TTS 是两套独立服务**，凭证和端点都不同。

MiMo TTS 由小米官方提供（`https://api.xiaomimimo.com/v1`），同样采用 OpenAI 兼容协议，但有两点关键差异：

1. **认证头不同**：MiMo 用 `api-key: $KEY`，而 OpenAI SDK 默认发 `Authorization: Bearer $KEY`。直接用 `openai.OpenAI(api_key=...)` 会被 MiMo 拒绝（401）。
2. **凭证独立**：需单独申请 MiMo API Key，不能复用 `ALIGO_API_KEY`。

因此后端实现需用 `httpx` 直接发请求（或在 OpenAI SDK 注入自定义 `DefaultHttpxClient` 设置 `api-key` 头），并在 `config.py` 中新增 `TTS_CONFIG`。

**请求示例（已实测通过）：**

```bash
curl https://api.xiaomimimo.com/v1/chat/completions \
  -H "api-key: $MIMO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "mimo-v2.5-tts",
    "messages": [
      {"role": "user", "content": "用自然亲切的语气朗读"},
      {"role": "assistant", "content": "你好，欢迎使用Aligo智能旅行助手。"}
    ],
    "audio": {"format": "pcm16", "voice": "冰糖"},
    "stream": true
  }'
```

**结论：可调用，但需独立配置 + httpx 直接请求，详见 §2.6。**

### 2.2 模型选择

推荐 **`mimo-v2.5-tts`**（预置音色），是目前唯一支持真正流式输出的模型。

| 模型 | 流式 | 适用场景 |
|------|------|----------|
| `mimo-v2.5-tts` | **真正流式**（低延迟） | 实时朗读 AI 回复 |
| `mimo-v2.5-tts-voicedesign` | 降级兼容（全部完成才返回） | 定制音色，不要求实时 |
| `mimo-v2.5-tts-voiceclone` | 降级兼容（全部完成才返回） | 复刻特定人声 |

### 2.4 TTS 调用规则

关键约定（来自 MiMo 官方文档）：

- **目标文本**放在 `role: assistant` 的消息中
- **风格指令**放在 `role: user` 的消息中（可选）
- **流式输出**必须指定 `format: "pcm16"`，以便前端拼接播放

### 2.5 架构

```
AI 回复文字 → POST /api/tts → MiMo TTS 流式合成 → PCM16 音频块 (SSE)
                                                   ↓
                                        前端 Web Audio API 实时播放
```

#### 2.6.2 路由实现（`server/routes/tts.py`）

**关键点**：MiMo 用 `api-key` 头认证（不是 `Authorization`），因此不能用 `openai.OpenAI(...)` 直接调用，需用 `httpx` 发原生请求。

**请求**：

```
POST /api/tts
Content-Type: application/json

{
  "text": "AI回复的文字内容",
  "voice": "冰糖",
  "style": "用轻松愉快的语气朗读，像一个热情的导游"
}
```

**响应**（SSE 流，与 MiMo 上游结构对齐）：

```
event: audio
data: {"chunk": "<base64 pcm16>", "index": 0}

event: audio
data: {"chunk": "<base64 pcm16>", "index": 1}

...

event: done
data: {}
```

**核心代码**：

```python
"""TTS SSE 流式端点"""
import json
import logging
from typing import AsyncIterator

import httpx
from fastapi import APIRouter
from pydantic import BaseModel
from sse_starlette.sse import EventSourceResponse

from config import TTS_CONFIG

logger = logging.getLogger(__name__)
router = APIRouter()


class TTSRequest(BaseModel):
    text: str
    voice: str | None = None
    style: str | None = None


async def _stream_mimo(text: str, voice: str, style: str) -> AsyncIterator[dict]:
    """流式调用 MiMo TTS，按 chunk 透传给前端。"""
    payload = {
        "model": TTS_CONFIG["model"],
        "messages": [
            {"role": "user", "content": style or TTS_CONFIG["default_style"]},
            {"role": "assistant", "content": text},
        ],
        "audio": {"format": "pcm16", "voice": voice},
        "stream": True,
    }
    headers = {
        "api-key": TTS_CONFIG["api_key"],
        "Content-Type": "application/json",
    }
    url = f"{TTS_CONFIG['base_url']}/chat/completions"

    idx = 0
    try:
        async with httpx.AsyncClient(timeout=httpx.Timeout(60.0, connect=5.0)) as client:
            async with client.stream("POST", url, headers=headers, json=payload) as resp:
                if resp.status_code != 200:
                    body = await resp.aread()
                    logger.error(f"[TTS] upstream {resp.status_code}: {body[:200]}")
                    yield {"event": "error", "data": json.dumps({"message": "TTS 服务异常"}, ensure_ascii=False)}
                    return

                async for line in resp.aiter_lines():
                    if not line or not line.startswith("data:"):
                        continue
                    data_str = line[5:].strip()
                    if data_str == "[DONE]":
                        break
                    try:
                        chunk = json.loads(data_str)
                    except json.JSONDecodeError:
                        continue
                    delta = chunk.get("choices", [{}])[0].get("delta", {})
                    audio = delta.get("audio")
                    if audio and audio.get("data"):
                        yield {"event": "audio", "data": json.dumps({"chunk": audio["data"], "index": idx}, ensure_ascii=False)}
                        idx += 1
    except httpx.HTTPError as e:
        logger.exception("[TTS] upstream connection failed")
        yield {"event": "error", "data": json.dumps({"message": f"TTS 连接失败: {e}"}, ensure_ascii=False)}
        return

    yield {"event": "done", "data": "{}"}


@router.post("/api/tts")
async def tts(req: TTSRequest):
    voice = req.voice or TTS_CONFIG["default_voice"]
    style = req.style or TTS_CONFIG["default_style"]
    return EventSourceResponse(_stream_mimo(req.text, voice, style))
```

### 2.7 前端新增

#### 关键发现（实测）

1. **MiMo 返回裸 PCM16**，无 WAV/RIFF 头（即便请求 `"format": "wav"` 也一样）。前端必须自己处理裸 PCM。
2. **每个 chunk 边界不一定按完整采样对齐**，需缓冲到偶数字节再解码。
3. **采样率未在响应中明示**，按 MiMo 官方文档为 **24kHz 单声道**，必须显式 `new AudioContext({ sampleRate: 24000 })`，否则会用浏览器默认 44.1kHz/48kHz 导致变调。

#### 新增 `web/src/hooks/useTTSPlayer.ts`

```ts
class TTSPlayer {
  private audioContext: AudioContext | null = null
  private nextPlayTime: number = 0
  private abortController: AbortController | null = null
  private readonly SAMPLE_RATE = 24000  // MiMo PCM16 固定 24kHz
  private readonly PREBUFFER_CHUNKS = 2 // 预缓冲 2 个 chunk 再开播，避免抖动

  private ensureContext(): AudioContext {
    if (!this.audioContext) {
      this.audioContext = new AudioContext({ sampleRate: this.SAMPLE_RATE })
    }
    return this.audioContext
  }

  async play(text: string, voice: string = '冰糖') {
    // 1. AudioContext 延迟启动（浏览器自动播放策略）
    const ctx = this.ensureContext()
    if (ctx.state === 'suspended') {
      await ctx.resume()
    }

    // 2. 重置播放游标
    this.nextPlayTime = ctx.currentTime
    this.abortController = new AbortController()

    // 3. 建立 SSE 连接到 /api/tts（用 fetch + getReader，与 sendChatMessage 一致）
    const resp = await fetch('/api/tts', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ text, voice }),
      signal: this.abortController.signal,
    })
    const reader = resp.body?.getReader()
    if (!reader) throw new Error('No response body')

    const decoder = new TextDecoder()
    let buffer = ''
    let pendingBytes: number[] = []  // 跨 chunk 的奇数字节缓冲
    let chunkQueue: AudioBuffer[] = []
    let started = false

    const scheduleQueue = () => {
      // 预缓冲足够 chunk 后开始播放，之后随到随播
      if (!started && chunkQueue.length >= this.PREBUFFER_CHUNKS) {
        started = true
      }
      while (started && chunkQueue.length > 0) {
        const buf = chunkQueue.shift()!
        const src = ctx.createBufferSource()
        src.buffer = buf
        src.connect(ctx.destination)
        // 精确调度：如果 nextPlayTime 落后于当前时间，从当前时间开始
        const startAt = Math.max(this.nextPlayTime, ctx.currentTime)
        src.start(startAt)
        this.nextPlayTime = startAt + buf.duration
      }
    }

    try {
      while (true) {
        const { done, value } = await reader.read()
        if (done) break

        buffer += decoder.decode(value, { stream: true })
        const lines = buffer.split('\n')
        buffer = lines.pop() || ''

        for (const line of lines) {
          if (line.startsWith('event:')) continue
          if (!line.startsWith('data:')) continue
          const dataStr = line.slice(5).trim()
          if (!dataStr) continue
          try {
            const data = JSON.parse(dataStr)
            if (data.chunk) {
              // 4. base64 → 字节数组，处理奇数字节边界
              const bytes = atob(data.chunk)
              const all = [...pendingBytes, ...bytes].map(c => c.charCodeAt(0))
              pendingBytes = all.length % 2 !== 0 ? [all.pop()!] : []

              // 5. Int16 → Float32（归一化到 [-1, 1]）
              const samples = new Int16Array(all.length / 2)
              for (let i = 0; i < samples.length; i++) {
                samples[i] = (all[i * 2] | (all[i * 2 + 1] << 8))
              }
              const float32 = new Float32Array(samples.length)
              for (let i = 0; i < samples.length; i++) {
                float32[i] = samples[i] / 32768
              }

              // 6. → AudioBuffer
              const audioBuf = ctx.createBuffer(1, float32.length, this.SAMPLE_RATE)
              audioBuf.copyToChannel(float32, 0)
              chunkQueue.push(audioBuf)
              scheduleQueue()
            }
          } catch (e) {
            // ignore parse errors
          }
        }
      }
    } finally {
      reader.releaseLock()
    }
  }

  stop() {
    this.abortController?.abort()
    this.abortController = null
    if (this.audioContext) {
      this.nextPlayTime = this.audioContext.currentTime
    }
  }
}
```

用 curl 对 `https://api.xiaomimimo.com/v1/chat/completions` 进行了 5 组测试：

| # | 模型 | format | stream | voice | HTTP | 大小 | 耗时 |
|---|------|--------|--------|-------|------|------|------|

| 4 | `mimo-v2.5-tts` | pcm16 | 是 | `Mia` | ✅ 200 | 199KB | **1.68s** |

**测试 4 的 SSE 结构**（关键）：

```
data: {"id":"...","object":"chat.completion.chunk","model":"mimo-v2.5-tts",
       "choices":[{"index":0,"delta":{"role":"assistant","content":"",
       "audio":{"id":"...","data":"<base64 pcm16>"}},"finish_reason":null}]}

data: {"id":"...","choices":[{"index":0,"delta":{"audio":{"data":"..."}}}]}

...

data: [DONE]
```

**关键发现**：

1. ✅ `mimo-v2.5-tts` 流式可用，SSE 协议与 OpenAI chat completion chunk 一致
2. ✅ 音频数据在 `choices[0].delta.audio.data`（base64 编码）
3. ✅ 流末尾发送 `data: [DONE]`
4. ⚠️ 返回**裸 PCM16**，无 WAV/RIFF 头（即便请求 `format: "wav"` 也一样）
5. ⚠️ 认证头是 `api-key`，不是 `Authorization: Bearer`
6. ⚠️ 第一个音频 chunk 大小 7680 字节（3840 个采样），首块延迟约 200-400ms

### 2.10 延迟分析（实测）

实测短句"Hello, welcome to Aligo travel assistant."的合成耗时：

| 模式 | 总大小 | 总耗时 | 首块估算 |
|------|--------|--------|----------|
| 流式（stream=true, pcm16） | 199KB | **1.68s** | ~200-400ms |
| 非流式（stream=false, pcm16） | 185KB | 3.09s | — |

```
AI 文字生成完成 → 前端发起 /api/tts → 后端建立 httpx 连接 → MiMo 首块
   ~0ms            ~50ms                    ~100ms              ~200-400ms
                                                                    ↓
                                              前端预缓冲 2 chunk → 开始播放
                                                  ~50-100ms
                                              ─────────────────────────────
                                              总首音延迟：~400-700ms
```

**实测链路**：流式总耗时 1.68s（合成完成），首个 SSE 事件含音频数据通常在 200-400ms 内到达。前端预缓冲 2 个 chunk 后开播，**用户感知首音延迟约 400-700ms**，可接受。

非流式比流式慢约 2 倍，且无法边收边播，**强烈推荐用流式模式**。

## 四、潜在风险与应对

| 风险 | 应对 |
|------|------|
| **MiMo 需独立 API Key（与阿里云 MAAS 不通用）** | `config.py` 新增 `TTS_CONFIG`，`.env` 新增 `MIMO_API_KEY` |
| **MiMo 用 `api-key` 头，OpenAI SDK 默认发 `Authorization`** | 后端用 `httpx` 直接发请求，绕开 SDK |
| **MiMo 返回裸 PCM16（无 WAV 头），即使请求 `format: wav`** | 前端固定按裸 PCM16 处理 |
| **AudioContext 默认采样率 44.1/48kHz，与 MiMo 24kHz 不匹配** | 显式 `new AudioContext({ sampleRate: 24000 })`，否则变调 |
| **PCM16 chunk 边界可能不在完整采样处** | 前端缓冲奇数字节到下一个 chunk |
| iOS Safari 要求 HTTPS 才能用麦克风 | 生产环境部署 HTTPS；开发环境 localhost 不受限 |
| Firefox 不支持 SpeechRecognition | `isSupported` 检测，不支持的浏览器隐藏麦克风按钮 |
| AudioContext 自动播放被浏览器阻止 | 首次需用户点击 "朗读" 按钮触发（满足浏览器策略） |
| 长文本 TTS 合成时间较长 | 流式返回 + 边收边播 + 预缓冲 2 chunk |
| TTS API 调用失败 | 复用现有 `circuit_breaker` 熔断机制（需在 `_stream_mimo` 外层包装） |
| 网络抖动导致 chunk 间隔不均 | `nextPlayTime` 精确调度 + 预缓冲，落后于当前时间时从当前时间开始播放 |
